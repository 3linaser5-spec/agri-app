# متابعة المحاصيل بالأقمار الصناعية في نباتي

## ما الذي أصبح جاهزاً في فرع الميزة

أصبحت الميزة **قسمًا مستقلًا** باسم «متابعة المحاصيل بالأقمار الصناعية» داخل قائمة الخدمات، منفصلًا عن شاشة «مزرعتي». يطلب المزارع التفعيل من داخل القسم، ويفعّله الأدمن يدويًا بالسعر والمدة وحد القطع ومساحة القطعة وعدد التحليلات الشهري.

يضيف العميل قطع أرض متعددة، ولكل قطعة اسم ونوع محصول وصنف وتاريخ زراعة ومساحة محسوبة من حدودها، ويعرض القسم إجمالي عدد القطع وإجمالي الفدادين وعدد المحاصيل المختلفة.

عند طلب التحليل يرسل الخادم حدود القطعة إلى **NASA AppEEARS Area API**، ويطلب المؤشرات التسعة من منتجي NASA HLS‑VI: `HLSS30_VI.020` (Sentinel‑2) و`HLSL30_VI.020` (Landsat)، لفترة آخر 90 يومًا. لا يحسب التطبيق المؤشر على الهاتف، ولا يستخدم Sentinel Hub. يُحفظ معرّف مهمة NASA في Firestore، وتفحص دالة مجدولة المهمة كل خمس دقائق، ثم تقرأ إحصاءات المساحة وتحدّث سجل القراءات تلقائيًا.

**مصدر البيانات الحسابية منفصل عن طبقة خريطة الرسم.** AppEEARS/HLS يمدّ التحليل بالقيم، بينما MapTiler يعرض خلفية فضائية لتحديد الحدود فقط. وجود خلفية فضائية في الخريطة لا يعني أنها صورة مؤشرات.

## المؤشرات التسعة ومعناها للمزارع

المنتجات الجاهزة HLS‑VI تحتوي تسعة مؤشرات، ويعرضها التطبيق بالعربية مع تفسير مختصر لكل مؤشر:

| المؤشر | الاستخدام الزراعي |
| --- | --- |
| NDVI | حيوية النبات وكثافة الغطاء الأخضر عمومًا |
| EVI | أدق في الغطاء الكثيف، وأقل تأثرًا بالتربة والجو |
| SAVI | يقلل أثر التربة الظاهرة في بداية النمو |
| MSAVI | نسخة مطوّرة من SAVI لا تحتاج ضبط معامل التربة |
| NDMI | محتوى الماء في أوراق النبات، وليس رطوبة التربة مباشرة |
| NDWI | المسطحات المائية والمياه الراكبة بين النباتات |
| NBR | التلف الشديد والحروق وتغيّر نوع الغطاء |
| NBR2 | يُستخدم مع NBR لفصل الرطوبة عن آثار الحرق |
| TVI | قراءة إضافية لكثافة الغطاء بمنظور طيفي مختلف |

## تحديد أماكن المشكلة داخل القطعة

يقسّم الخادم مضلع القطعة إلى شبكة داخلية (حتى تسعة أجزاء، وتُستبعد الأجزاء الفارغة أو الضئيلة)، ويرسل كل جزء إلى NASA كمنطقة مستقلة داخل الطلب نفسه. تعود الإحصاءات لكل منطقة بمعرّفها (`Z01`, `Z02` …)، ويحفظ الخادم القيمة لكل منطقة ولكل مؤشر لكل يوم.

تعرض شاشة القطعة خريطة المناطق ملوّنة حسب الفارق عن متوسط القطعة للمؤشر المختار: أحمر عند الانخفاض الواضح، برتقالي عند انخفاض أقل، أخضر عند التماثل أو الارتفاع. وتظهر قائمة بالأجزاء الأضعف مع القيمة ومقدار الفارق وتنبيه لمراجعة الري والتغذية والحشرات في ذلك الجزء تحديدًا.

هذا التقسيم **تقريبي وليس مسحًا حقليًا**؛ الهدف توجيه الفحص إلى الجزء الأضعف لا إصدار تشخيص. الجزء الصغير قد يحتوي بكسلات قليلة مختلطة مع التربة أو حواف القطعة.

## دقة البيانات وحدود التفسير

منتجات HLS‑VI توفر المؤشرات جاهزة بدقة مكانية **30 مترًا** وبمقياس بيانات 0.0001. يدمج HLS مشاهد Landsat وSentinel‑2؛ لكن كثافة المشاهد الصافية تختلف حسب السحب وتوفر البيانات. البكسل الواحد يمثل نحو 900 م²، لذلك القطع الصغيرة قد تحتوي عددًا قليلًا من البكسلات المختلطة. استخدم النتيجة كمؤشر متابعة، لا كتشخيص مرض أو توصية ري أو مبيدات مستقلة.

- [كتالوج NASA الرسمي لمنتج HLSS30_VI](https://www.earthdata.nasa.gov/data/catalog/lpcloud-hlss30-vi-2.0)
- [كتالوج NASA الرسمي لمنتج HLSL30_VI](https://www.earthdata.nasa.gov/data/catalog/lpcloud-hlsl30-vi-2.0)
- [توثيق NASA AppEEARS API](https://appeears.earthdatacloud.nasa.gov/api/)
- [دليل NASA الرسمي لطلبات المناطق AppEEARS](https://lpdaac.usgs.gov/documents/626/AppEEARS_API_Area.html)
- [تسجيل NASA Earthdata Login](https://www.earthdata.nasa.gov/data/earthdata-login)

## مجانيّة البيانات وما قد يظل له تكلفة

بيانات NASA Earth science مفتوحة بلا رسوم ترخيص، لكن تنزيل البيانات واستخدام نقاط النهاية المحمية يتطلب حساب Earthdata Login، وAppEEARS خدمة معالجة واستخراج لها شروط تشغيل وحدود استخدام يجب مراجعتها قبل تقديمها تجاريًا على نطاق واسع. **NASA CMR فهرس للبحث عن البيانات والبيانات الوصفية؛ ليس محركًا يحلل مضلع المزرعة بذاته.**

مجانية ملفات HLS لا تعني أن التطبيق كله بلا تكلفة: قد تترتب رسوم على Cloud Functions والمجدول وFirestore ونقل البيانات، كما أن استخدام MapTiler التجاري منفصل عن NASA. طلب تسعة مؤشرات لتسع مناطق يضاعف عدد الملفات التي تعالجها NASA مقارنة بطلب NDVI واحد، فراجع حجم الطلبات وحدود الحساب قبل التوسع لعملاء كثر.

## الإعداد قبل الاختبار

1. أنشئ حساب Earthdata Login، ثم تحقق من تسجيل الدخول إلى AppEEARS. استخدم حسابًا مخصصًا لخادم التطبيق وفق شروط NASA، ولا تضع كلمة المرور في Flutter أو ملفات Git.
2. أضف أسرار NASA إلى Firebase Functions من الطرفية في مجلد المشروع:

   ```bash
   firebase functions:secrets:set APPEEARS_USERNAME
   firebase functions:secrets:set APPEEARS_PASSWORD
   ```

   أدخل القيم في المطالبات السرية عند التنفيذ. لا ترسلها في المحادثة ولا تضعها كمتغيرات عادية في GitHub Actions. تحصل الدوال على رمز AppEEARS مؤقت عند كل تشغيل، ثم تستخدمه لطلب بيانات NASA.
3. أنشئ مفتاح MapTiler مقيدًا للاستخدام المطلوب، وضعه في GitHub **Settings → Secrets and variables → Actions** باسم `MAPTILER_API_KEY`. المفتاح الذي يصل إلى APK قابل للاستخراج، لذا قيّده ولا تعتبره سرًا خادميًا. راجع [أسعار MapTiler الحالية](https://www.maptiler.com/cloud/pricing/) قبل الاستخدام التجاري.
4. تحقق من وجود مستند UID الأدمن في `/admins/{uid}`؛ لا تمنح صلاحية الأدمن بمجرد البريد.
5. فعّل App Check وسجل Debug token المناسب عند اختبار نسخة Debug؛ الدوال تحمي callable requests بواسطة `enforceAppCheck: true`.
6. اختبر يدويًا أن المنتجات والطبقات التسع متاحة في كتالوج [AppEEARS Products](https://appeears.earthdatacloud.nasa.gov/products)، وأن حساب Earthdata يملك صلاحية استخدام API.

## الاختبار والنشر بعد مراجعة الفرع

لم تُنشر هذه الدوال أو القواعد أو الفهارس بواسطة هذا التغيير. نشر Functions الجيل الثاني والأسرار والمجدول يتطلب مشروع Firebase/Google Cloud بخطة فوترة ملائمة؛ لا تنفذ النشر قبل مراجعة الفوترة وحدود AppEEARS والموافقة على المشروع النشط.

بعد تجهيز الأسرار ومراجعة التغييرات، يمكن نشر وظائف مراقبة الأقمار الثلاثة ومعالج النتائج المجدول ثم قواعد وفهارس Firestore:

```bash
firebase deploy --only functions:requestSatelliteNdvi,functions:saveSatelliteField,functions:deleteSatelliteField,functions:processSatelliteNdviJobs
firebase deploy --only firestore:rules,firestore:indexes
```

## ملاحظات تشغيلية

- يخصم الخادم محاولة من الحصة الشهرية عند قبول AppEEARS للمهمة؛ إذا فشل إرسال المهمة أو انتهت بحالة خطأ خادمية، يعيد الخادم المحاولة إلى الحصة. تعذر المشهد الصافي أو غياب بيانات صالحة قد ينتج حالة بلا قراءات، وليس دليلًا على تلف القطعة.
- إذا انقطع الاتصال بعد إرسال المهمة وقبل استلام معرّفها، يحفظ الخادم اسم NASA الفريد ويبحث عنه في قائمة مهام AppEEARS قبل إعادة الحصة؛ الطلبات غير المحسومة تنتهي بمهلة محددة، وفشل المصادقة المتكرر لا يترك الحصة معلقة بلا نهاية.
- إنشاء القطع وحذفها يحدّثان مستند الاشتراك المشترك ضمن معاملة Firestore، إلى جانب فحص العدد الفعلي، لمنع تجاوز حد القطع بطلبات متزامنة.
- عند تعديل حدود قطعة، يعيد الخادم توليد تقسيم المناطق ويحفظه مع القطعة، فتصبح القراءات اللاحقة مطابقة للحدود الجديدة.
- لا تسمح شاشة التطبيق بكتابة نتائج المؤشرات؛ تكتبها الدوال الخادمية فقط ويقرأها صاحب القطعة. مهام NASA محفوظة في مجموعة خادمية لا تمنح قواعد العميل حق الوصول إليها.
- قد تستغرق المهمة وقتًا؛ تبقى الواجهة تعرض حالة الانتظار، ثم تُحدّث النتائج تلقائيًا عند انتهاء المجدول من المعالجة.
- حدود المضلع تقديرية وليست مسحًا مساحيًا قانونيًا. يجب تفسير المؤشرات بحسب المحصول ومرحلة النمو وملاحظات المهندس الزراعي.
