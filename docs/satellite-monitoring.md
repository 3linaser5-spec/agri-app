# إعداد مراقبة المحصول بالأقمار الصناعية في نباتي

## ما الذي أصبح جاهزاً في فرع الميزة

تتضمن الشاشة طلب التفعيل للمزارع، ولوحة يدوية للأدمن لتحديد السعر والمدة وحد الحقول ومساحة الحقل وعدد التحليلات الشهري، ورسم حدود الحقول على خريطة فضائية. تحفظ Cloud Functions حدود الحقول وتتحقق خادمياً من الملكية والاشتراك والحصص.

عند طلب التحليل، يرسل الخادم مضلع الحقل إلى **NASA AppEEARS Area API** لطلب طبقة NDVI الجاهزة من منتجي NASA HLS‑VI: `HLSS30_VI.020` (Sentinel‑2) و`HLSL30_VI.020` (Landsat)، لفترة آخر 90 يوماً. لا يحسب التطبيق المؤشر على الهاتف ولا يستدعي Sentinel Hub. يُحفظ معرّف المهمة في Firestore، وتفحصه دالة مجدولة كل خمس دقائق؛ وبعد اكتمال المهمة تقرأ إحصاءات المساحة وتحدّث سجل NDVI تلقائياً.

**مصدر البيانات الحسابية منفصل عن طبقة خريطة الرسم.** AppEEARS/HLS يمدّ التحليل بقيم NDVI، بينما MapTiler يعرض خلفية فضائية لتحديد الحدود فقط. وجود خلفية فضائية في الخريطة لا يعني أنها صورة NDVI.

## دقة البيانات وحدود التفسير

منتجات HLS‑VI توفر NDVI جاهزاً بدقة مكانية **30 متراً** وبمقياس بيانات 0.0001. يدمج HLS مشاهد Landsat وSentinel‑2؛ لكن كثافة المشاهد الصافية تختلف حسب السحب وتوفر البيانات. 30 متراً تعني أن البكسل الواحد يمثل نحو 900 م²؛ لذلك الحقول الصغيرة قد تحتوي عدداً قليلاً من البكسلات المختلطة مع التربة أو حواف الحقل. استخدم النتيجة كمؤشر متابعة، لا كتشخيص مرض أو توصية ري/مبيدات مستقلة.

- [كتالوج NASA الرسمي لمنتج HLSS30_VI](https://www.earthdata.nasa.gov/data/catalog/lpcloud-hlss30-vi-2.0)
- [كتالوج NASA الرسمي لمنتج HLSL30_VI](https://www.earthdata.nasa.gov/data/catalog/lpcloud-hlsl30-vi-2.0)
- [توثيق NASA AppEEARS API](https://appeears.earthdatacloud.nasa.gov/api/)
- [دليل NASA الرسمي لطلبات المناطق AppEEARS](https://lpdaac.usgs.gov/documents/626/AppEEARS_API_Area.html)
- [تسجيل NASA Earthdata Login](https://www.earthdata.nasa.gov/data/earthdata-login)

## مجانيّة البيانات وما قد يظل له تكلفة

بيانات NASA Earth science مفتوحة بلا رسوم ترخيص، لكن تنزيل البيانات واستخدام نقاط النهاية المحمية يتطلب حساب Earthdata Login، وAppEEARS خدمة معالجة/استخراج لها شروط تشغيل وحدود استخدام يجب مراجعتها قبل تقديمها تجارياً على نطاق واسع. **NASA CMR فهرس للبحث عن البيانات والبيانات الوصفية؛ ليس محركاً يحلل مضلع المزرعة بذاته.** التنفيذ هنا يستخدم AppEEARS لتقديم المضلع واستخراج إحصاء NDVI.

مجانية ملفات HLS لا تعني أن التطبيق كله بلا تكلفة: قد تترتب رسوم على Cloud Functions والمجدول وFirestore ونقل البيانات، كما أن استخدام MapTiler التجاري منفصل عن NASA. راجع حدود الخدمات والفوترة قبل تفعيل عملاء مدفوعين.

## الإعداد قبل الاختبار

1. أنشئ حساب Earthdata Login، ثم تحقق من تسجيل الدخول إلى AppEEARS. استخدم حساباً مخصصاً لخادم التطبيق وفق شروط NASA، ولا تضع كلمة المرور في Flutter أو ملفات Git.
2. أضف أسرار NASA إلى Firebase Functions من الطرفية في مجلد المشروع:

   ```bash
   firebase functions:secrets:set APPEEARS_USERNAME
   firebase functions:secrets:set APPEEARS_PASSWORD
   ```

   أدخل القيم في المطالبات السرية عند التنفيذ. لا ترسلها في المحادثة ولا تضعها كمتغيرات عادية في GitHub Actions. تحصل الدوال على رمز AppEEARS مؤقت عند كل تشغيل، ثم تستخدمه لطلب بيانات NASA.
3. أنشئ مفتاح MapTiler مقيداً للاستخدام المطلوب، وضعه في GitHub **Settings → Secrets and variables → Actions** باسم `MAPTILER_API_KEY`. المفتاح الذي يصل إلى APK قابل للاستخراج، لذا قيّده ولا تعتبره سراً خادمياً. راجع [أسعار MapTiler الحالية](https://www.maptiler.com/cloud/pricing/) قبل الاستخدام التجاري.
4. تحقق من وجود مستند UID الأدمن في `/admins/{uid}`؛ لا تمنح صلاحية الأدمن بمجرد البريد.
5. فعّل App Check وسجل Debug token المناسب عند اختبار نسخة Debug؛ الدوال تحمي callable requests بواسطة `enforceAppCheck: true`.
6. اختبر يدوياً أن المنتجات والطبقة `NDVI` متاحة في كتالوج [AppEEARS Products](https://appeears.earthdatacloud.nasa.gov/products)، وأن حساب Earthdata يملك صلاحية استخدام API.

## الاختبار والنشر بعد مراجعة الفرع

لم تُنشر هذه الدوال أو القواعد أو الفهارس بواسطة هذا التغيير. نشر Functions الجيل الثاني والأسرار والمجدول يتطلب مشروع Firebase/Google Cloud بخطة فوترة ملائمة؛ لا تنفذ النشر قبل مراجعة الفوترة وحدود AppEEARS والموافقة على المشروع النشط.

بعد تجهيز الأسرار ومراجعة التغييرات، يمكن نشر وظائف مراقبة الأقمار الثلاثة ومعالج النتائج المجدول ثم قواعد/فهارس Firestore:

```bash
firebase deploy --only functions:requestSatelliteNdvi,functions:saveSatelliteField,functions:deleteSatelliteField,functions:processSatelliteNdviJobs
firebase deploy --only firestore:rules,firestore:indexes
```

## ملاحظات تشغيلية

- يخصم الخادم محاولة من الحصة الشهرية عند قبول AppEEARS للمهمة؛ إذا فشل إرسال المهمة أو انتهت بحالة خطأ خادمية، يعيد الخادم المحاولة إلى الحصة. تعذر المشهد الصافي أو غياب بيانات صالحة قد ينتج حالة بلا قراءات، وليس دليلاً على تلف الحقل.
- إذا انقطع الاتصال بعد إرسال المهمة وقبل استلام معرّفها، يحفظ الخادم اسم NASA الفريد ويبحث عنه في قائمة مهام AppEEARS قبل إعادة الحصة؛ الطلبات غير المحسومة تنتهي بمهلة محددة، وفشل المصادقة المتكرر لا يترك الحصة معلقة بلا نهاية.
- إنشاء الحقول وحذفها يحدّثان مستند الاشتراك المشترك ضمن معاملة Firestore، إلى جانب فحص العدد الفعلي، لمنع تجاوز حد الحقول بطلبات متزامنة.
- لا تسمح شاشة التطبيق بكتابة نتائج NDVI؛ تكتبها الدوال الخادمية فقط ويقرأها صاحب الحقل. مهام NASA نفسها محفوظة في مجموعة خادمية لا تمنح قواعد العميل حق الوصول إليها.
- قد تستغرق المهمة وقتاً؛ تبقى الواجهة تعرض حالة الانتظار، ثم تُحدّث النتائج عند انتهاء المجدول من المعالجة.
- حدود المضلع تقديرية وليست مسحاً مساحياً قانونياً. يجب تفسير NDVI بحسب المحصول ومرحلة النمو وملاحظات المهندس الزراعي.
