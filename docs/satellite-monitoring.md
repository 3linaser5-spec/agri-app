# إعداد مراقبة المحصول بالأقمار الصناعية في نباتي

## ما الذي أصبح جاهزاً في الفرع

أُضيفت شاشة مزارع لطلب التفعيل ومتابعة حالته، وشاشة أدمن لتسجيل السعر والمدة وحد الحقول وأقصى مساحة لكل حقل وعدد تحليلات NDVI الشهرية لكل UID. يرسم المستخدم حدود الحقل فوق طبقة MapTiler الفضائية، بينما تحفظ Cloud Functions المضلع وتحسب مساحته وتتحقق من ملكية المستخدم ومن حدود الباقة.

عند طلب التحليل، تتحقق الدالة من صلاحية الاشتراك وتستهلك حصة شهرية في معاملة Firestore قبل استدعاء Sentinel Hub Statistical API. تُستخرج متوسطات NDVI على فترات 15 يوماً لآخر 90 يوماً من Sentinel‑2 L2A، وتُحجب فئات السحب والماء والبيانات غير الصالحة. تحفظ النتائج في `satellite_fields/{fieldId}/ndvi_history` ويقرأها صاحب الحقل فقط. نتائج NDVI مؤشر عام وليست تشخيصاً لمرض أو بديلاً عن الفحص الحقلي.

**طبقة الخريطة الفضائية ليست صورة NDVI.** MapTiler مخصص لرؤية الأرض ورسم حدودها. أما NDVI فيُحسب خادمياً من النطاقين الأحمر B04 وتحت الأحمر القريب B08 في Sentinel‑2. قد تختلف مواعيد الصور وحدود الدقة والسحب بين الطبقتين.

## الإعداد المطلوب قبل الاختبار الفعلي

1. أنشئ مفتاح MapTiler واستخدم خطة تسمح بالاستخدام التجاري. وفق صفحة الأسعار الرسمية وقت إعداد هذا المستند، الخطة المجانية للاختبار والاستخدام غير التجاري، وخطة Flex التجارية تبدأ من 30 دولاراً شهرياً وتضم 25 ألف جلسة و500 ألف طلب API؛ الاستخدام الإضافي له رسوم. راجع الأسعار الحالية وحدود الاستهلاك قبل تفعيل الخدمة للعملاء. [الأسعار الرسمية](https://www.maptiler.com/cloud/pricing/)
2. قيّد مفتاح MapTiler من لوحة الحساب على تطبيقك والاستخدام المطلوب. المفتاح الذي يصل إلى التطبيق يمكن استخراجه من APK، لذلك لا تتعامل معه كسرّ خادمي ولا تتركه بلا قيود.
3. في مستودع GitHub افتح **Settings → Secrets and variables → Actions** وأنشئ السر `MAPTILER_API_KEY`. يبني workflow الفرع `feature/satellite-crop-monitoring` المفتاح داخل التطبيق وقت البناء. من دونه تظهر شاشة توضح أن الخريطة غير مُعدة.
4. أنشئ بيانات OAuth لخدمة Sentinel Hub من حسابك، ثم خزّنها كأسرار Firebase Functions، لا في Flutter أو GitHub كقيم مكشوفة:

   ```bash
   firebase functions:secrets:set SENTINEL_HUB_CLIENT_ID
   firebase functions:secrets:set SENTINEL_HUB_CLIENT_SECRET
   ```

   واجهة Sentinel Hub Statistical API الرسمية تستخدم `sentinel-2-l2a`، وهندسة GeoJSON، وEvalscript لحساب الإحصاءات من B04/B08؛ راجع [مرجع Statistical API](https://docs.sentinel-hub.com/api/latest/api/statistical/) و[أمثلة NDVI](https://docs.sentinel-hub.com/api/latest/api/statistical/examples/). بيانات Copernicus Sentinel لها ترخيص استخدام تجاري، لكن رسوم أو حصص خدمة المعالجة السحابية تعتمد على حساب المزود وخطته؛ تحقق منها قبل تشغيل طلبات العملاء.
5. تحقق من أن UID الأدمن لديه مستند `/admins/{uid}` في Firestore. التحقق البصري بالبريد وحده لا يمنح صلاحية الكتابة؛ قواعد Firestore تتحقق من مستند UID هذا.
6. فعّل App Check للتطبيق، وسجّل Debug token المخصص للاختبار عند استخدام نسخة Debug. دوال NDVI وحفظ/حذف الحدود تستخدم `enforceAppCheck: true`.

## النشر بعد مراجعة الفرع

لم تُنشر الدوال أو القواعد أو الفهارس من هذا التغيير. بعد إعداد الأسرار ومراجعة قواعد Firestore، تُنشر الدوال الثلاثة والقواعد/الفهارس بالأوامر التالية من جذر المشروع:

```bash
firebase deploy --only functions:requestSatelliteNdvi,functions:saveSatelliteField,functions:deleteSatelliteField
firebase deploy --only firestore:rules,firestore:indexes
```

تحتاج Cloud Functions إلى خطة Firebase/Google Cloud تسمح بتشغيلها وإعداد الأسرار. لا تشغّل أوامر النشر قبل التأكد من مشروع Firebase النشط، وحدود الاستخدام والتكلفة.

## ملاحظات التشغيل

- طلب التحليل يحتسب من الحصة الشهرية قبل استدعاء مزود الصور لمنع طلبات متزامنة تتجاوز الحد؛ قد تُستهلك محاولة إذا فشل المزود بعد حجز الحصة. عند تكرر الفشل، راجع سجلات الدوال قبل إعادة تفعيل رصيد المستخدم.
- نتائج NDVI تُظهر متوسط كل فترة صالحة؛ غياب نتيجة لفترة لا يعني تلف الحقل، فقد لا توجد مشاهدة صافية متاحة.
- قياس المساحة تقديري من المضلع الجغرافي، وليس مسحاً مساحياً قانونياً.
- قرارات الري أو المبيدات لا ينبغي ربطها آلياً بقراءة NDVI منفردة. يلزم تفسيرها بحسب نوع المحصول ومرحلة النمو وملاحظات المهندس الزراعي.
