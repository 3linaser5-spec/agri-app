# ملخص تحسينات agri-app

هذه الدفعة موجودة محليًا على الفرع `manus/audit-fixes`. لم تُدفع إلى GitHub، ولم تُنشر إلى Firebase، ولم يُنشر APK جديد. يلزم مراجعة التغييرات قبل دمجها أو نشرها.

## ما تم تحسينه

- **الحاسبات والقوالب:** جعل تقييم أسماء المتغيرات غير حساس لحالة الأحرف، ورفض معرّفات الحقول التي تختلف فقط بحالة الأحرف، وحجز `area` لمتغير مساحة الحقل، مع اختبارات تمنع رجوع الخلل.
- **الهاتف والمصادقة:** توحيد صيغ رقم المحمول المصري المحلية والدولية والأرقام العربية إلى صيغة محلية واحدة للحسابات الجديدة؛ دعم محاولة دخول ثانية بصيغة البريد القديمة للحسابات السابقة؛ إكمال ملف المستخدم عند غيابه بعد الدخول؛ ومعالجة الحساب الجزئي إذا فشل التسجيل قبل حفظ ملفه. أُضيف تنبيه في الواجهة بأن الهاتف **غير موثّق برسالة SMS**. هذا لا يساوي OTP ولا يثبت ملكية الرقم.
- **تنبيهات الطقس:** نقل تسجيل أجهزة FCM إلى Callable Function مصادق عليها مع تحقق من المدخلات، حد أقصى قدره 5 أجهزة لكل UID، وتقريب الإحداثيات على الخادم؛ ومنع الكتابات المباشرة على مجموعة الأجهزة في قواعد Firestore. أضيفت اختبارات لوحدة التحقق.
- **صلاحية الإدارة:** توحيد قرار إظهار لوحة الأدمن وفتحها على مستند `admins/<UID>` نفسه الذي تستخدمه قواعد Firestore، وإزالة قائمة البريد الثابتة من التطبيق.
- **Firestore:** تشديد مخطط المستندات المملوكة للمستخدم وتشخيصاته وبرامج المزرعة، وحصر التحديثات المسموح بها. شُغّل Firestore Emulator محليًا وقَبِل تحميل/تحليل ملف القواعد؛ لم تُنفذ مجموعة اختبارات سماح/منع كاملة، ولم تُنشر القواعد.
- **تعامل البيانات والأخطاء:** إظهار فشل تحميل أقسام وقوالب الحاسبات بدل تحويله إلى قائمة فارغة مضللة، وإزالة أخطاء تحليل Flutter الحالية.
- **التبعيات والتحديث الذاتي:** تحديث التبعيات المتأثرة في Cloud Functions؛ إضافة بصمة SHA-256 المحسوبة والمتحقق منها لملف APK المنشور v1.0.0 إلى `version.json`؛ إضافة `scripts/update_release_checksum.py` لتوليد بصمة الإصدارات اللاحقة؛ وجعل Workflow يرفع APK وملف البصمة ونسخة `version.json` المطابقة كـartifact.
- **GitHub Actions والتوقيع:** تقليل صلاحيات سير التحليل، تثبيت Actions على commit SHAs، حصر Workflow البناء الموقّع بفرع `main` وربطه ببيئة `android-release`، وعدم رفع keystore أو بياناته السرية. يتطلب هذا أن يضبط مالك المستودع البيئة والمراجعين والأسرار فعليًا.
- **قابلية إعادة البناء:** إضافة `pubspec.lock` بعد حل التبعيات والتحقق منها.

## نتائج التحقق

- `flutter test`: نجحت **64** حالة.
- `flutter analyze`: لا توجد ملاحظات.
- Cloud Functions: نجح البناء و**9** اختبارات Node.js/TypeScript.
- `npm audit --omit=dev`: **0 ثغرات**.
- Firestore Emulator: نجحت اختبارات سلوكية مؤقتة للقراءة بصلاحية المالك، ومنع مستخدم آخر، وإنشاء التشخيص والبرنامج المسموحين، وتقييد تعديلات البرنامج، ومنع إنشاء جهاز الطقس مباشرة. الاختبارات شُغّلت خارج المستودع ولم تُضف كحزمة دائمة إلى CI؛ لذا يلزم الحفاظ على اختبارات قواعد آلية للمستقبل.
- نجح `git diff --check`، والتحقق من صحة ملفات JSON المعدّلة.
- لم يُبنَ APK موقّع، ولم تُشغّل Actions على GitHub، ولم يُختبر أي نشر خارجي.

## عناصر تتطلب قرارًا أو إعدادًا من المالك

1. **مفتاح توقيع Android:** يذكر تاريخ المشروع أن keystore وكلمة مروره كُشفا سابقًا. لم أدوّر المفتاح أو الأسرار؛ قد يمنع ذلك تحديث التطبيق المنشور إن نُفّذ بلا مراعاة Play App Signing. راجع [دليل التوقيع](ANDROID_SIGNING_SETUP.md)، وسياسة Play App Signing، ثم غيّر/استبدل المفتاح والأسرار وفق خطة المالك.
2. **نشر Firebase:** لا تنشر القواعد قبل إتاحة Callable Function. يتطلب الانتقال تنسيق نشر بين الخادم والقواعد والتطبيق؛ العملاء الأقدم الذين ما زالوا يكتبون إلى مجموعة الأجهزة مباشرة قد يفشل تسجيلهم بعد تقييد القواعد. اختبر خطة الترحيل على المشروع الصحيح قبل الإنتاج.
3. **OTP:** تفعيل Phone Auth يغيّر تدفق التسجيل والدخول، ويتطلب إعداد Firebase Phone Auth، وتخطيط ترحيل الهويات الحالية وتكلفة SMS. لم يُفعّل هنا؛ التنبيه يوضح القيد للمستخدم.
4. **صلاحية الأدمن:** أنشئ مستند `admins/<UID>` للمسؤول المخوّل من خلال إجراء إداري موثوق؛ لا تُعد قائمة بريد داخل التطبيق مصدرًا للصلاحية.
5. **إصدارات APK:** Workflow يحسب البصمة ويحدّث manifest داخل artifact فقط؛ لا ينشئ GitHub Release ولا يحدّث الملف في الفرع. راجع APK والبيان وارفعهما معًا وفق إجراء الإصدار المعتاد.

## نشر تدريجي مقترح

1. اضبط `android-release`، والمراجعين المطلوبين، وأسرار التوقيع وFirebase في GitHub.
2. راجع التغييرات ثم ادمجها؛ انشر Cloud Function `registerWeatherPushDevice` أولًا.
3. اختبر Callable Function وقواعده على مشروع/بيئة اختبار، ثم جهّز إصدار APK وmanifest ببصمة متطابقة.
4. وزّع التطبيق وخطّط لأجهزة النسخ القديمة، ثم انشر Firestore Rules بعد التأكد من السلوك والانتقال.
5. نفّذ تدوير مفتاح التوقيع وPhone Auth فقط بعد استكمال قرارات وإعدادات المالك المناسبة.
