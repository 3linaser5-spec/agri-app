# إعداد توقيع Android بأمان

## المبدأ

إنشاء وإدارة مفتاح الإصدار يتمان **محلياً على جهاز يسيطر عليه مالك المستودع**. لا تنشئ Actions مفتاحاً، ولا تطبع keystore أو Base64، ولا ترفعهما كـ artifact. يستخدم Workflow البناء القيم الموجودة في GitHub Secrets مؤقتاً لإنشاء ملفات العمل ثم يحذف ملفات التوقيع المحلية من runner.

> **تحذير مهم:** تعديل Workflow لا يجعل مفتاحاً سبق كشفه آمناً. ملف `agri-release-key.jks` وكلمة المرور الثابتة التي ظهرت في Workflow القديم يجب اعتبارهما مكشوفين. أنشئ مفتاحاً جديداً، ودوّر الأسرار، واتبع سياسة النشر الخاصة بالتطبيق قبل اعتماد أي إصدار جديد. إذا كان التطبيق منشوراً، تحقّق أولاً من وضع Play App Signing ومتطلبات ترقية مفتاح الرفع/التوقيع حتى لا تفقد القدرة على تحديث التطبيق.

## إنشاء keystore محلياً

1. اختر جهازاً موثوقاً ومحدّثاً، وتأكد أن `keytool` من JDK مناسب مثبت عليه.
2. اختر alias ثابتاً وبيانات هوية صحيحة للمؤسسة. لا تستخدم كلمة مرور منسوخة من Workflow القديم، ولا تضع كلمات المرور في shell history أو ملفات المشروع.
3. نفّذ الأمر التالي محلياً بعد استبدال `CHOOSE_A_KEY_ALIAS` بقيمة يختارها المالك؛ سيطلب `keytool` كلمات المرور تفاعلياً:

   ```sh
   umask 077
   keytool -genkeypair -v \
     -keystore ./agri-release-key.jks \
     -keyalg RSA -keysize 2048 -validity 10000 \
     -alias CHOOSE_A_KEY_ALIAS \
     -dname "CN=Agri App, OU=Release, O=Owner, L=City, S=State, C=XX"
   ```

4. احفظ نسخة احتياطية مشفّرة من keystore في مخزن أسرار غير متصل أو مُدار من المؤسسة. لا تضعه في Git، ولا ترسله بالبريد أو ترفعه إلى artifact. احتفظ أيضاً بكلمات المرور في مدير أسرار منفصل؛ فقدانها يمنع استعمال المفتاح.
5. راجع الملف محلياً، من دون طباعته أو رفعه:

   ```sh
   keytool -list -v -keystore ./agri-release-key.jks
   ```

## إنشاء أسرار GitHub

من إعدادات المستودع، أضف **Repository secrets** بالأسماء التالية. لا تضع القيم في YAML أو source أو سجل CI:

| Secret | القيمة المطلوبة |
|---|---|
| `KEYSTORE_BASE64` | ناتج Base64 للملف `agri-release-key.jks` في سطر واحد؛ لا ترفع ملف Base64 كـ artifact |
| `KEYSTORE_PASSWORD` | كلمة مرور keystore الجديدة |
| `KEY_PASSWORD` | كلمة مرور المفتاح/alias الجديدة |
| `KEY_ALIAS` | alias الذي اختاره المالك عند إنشاء keystore |
| `GOOGLE_SERVICES_JSON` | ملف `google-services.json` مشفراً بصيغة Base64 كما يتوقع Workflow الحالي |

أنشئ القيمة أحادية السطر محلياً بالطريقة التالية، ثم الصقها مباشرة في Secret `KEYSTORE_BASE64` عبر GitHub أو استخدم مدير الأسرار المؤسسي:

```sh
base64 --wrap=0 ./agri-release-key.jks
```

لا تحفظ الناتج في ملف دائم، ولا تُظهره في سجل shell. بعد إدخال الأسرار، راجع صلاحيات الوصول إليها، وقيّد تشغيل Workflow إلى المراجعين الموثوقين، ولا تطبع `key.properties` أو محتويات الأسرار في خطوات CI.

## ما يجب على المالك إكماله

- إبطال/استبدال المفتاح القديم إذا ظهر في artifact أو سجل أو نسخة من المستودع، وتغيير كلمات المرور المرتبطة به؛ تنظيف الملف من Git لا يمحو النسخ السابقة.
- التحقق من تاريخ نشر التطبيق وPlay App Signing قبل اختيار مفتاح جديد، وتسجيل قرار الاستبدال وخطة التحديث.
- إنشاء الأسرار الخمسة أعلاه بالقيم الفعلية عبر GitHub Secrets، مع عدم إدخال أي قيمة سرية في هذا المستند. لا تضف `GEMINI_API_KEY`؛ التطبيق يستخدم Firebase AI Logic ولا ينبغي تضمين مفتاح Gemini في APK.
- اختبار البناء من خلال تشغيل Workflow لاحقاً بعد مراجعة الأسرار والصلاحيات؛ يجب أن يخرج artifact الـ APK فقط، لا keystore ولا Base64.
- الاحتفاظ بنسخة احتياطية مشفّرة من المفتاح وكلمات المرور خارج GitHub، مع وصول محدود وخطة استعادة.
