# إعداد إشعارات الطقس عبر Push

تضيف هذه الميزة مفتاح موافقة داخل بطاقة الطقس. بعد تفعيله، يسجّل التطبيق رمز FCM لهذا الحساب مع إحداثيات مقربة إلى منزلتين عشريتين فقط، أي دقة تقريبية تقارب كيلومتراً. Cloud Function مجدولة كل ثلاث ساعات تجلب توقعات الأيام الثلاثة القادمة من Open-Meteo وترسل تنبيهاً عبر Firebase Cloud Messaging عند تحقق عتبات المطر أو الحرارة أو البرودة نفسها المستخدمة داخل التطبيق. حالة منع التكرار محفوظة في مجموعة لا يستطيع العميل قراءتها أو كتابتها. إيقاف المفتاح أو تسجيل الخروج يحذف تسجيل هذا الجهاز من الخادم.

استخدمت الميزة واجهة رمز FCM المتوافقة مع `firebase_messaging ^16` و`firebase_core ^4` الموجودتين في المشروع. [توثيق Firebase الحالي](https://firebase.google.com/docs/cloud-messaging/flutter/get-started) يفضّل FID ويضع واجهات رموز FCM القديمة ضمن الواجهات المهجورة؛ والانتقال إلى FID يتطلب ترقية منسقة للحزم، لأن [firebase_messaging 17](https://pub.dev/packages/firebase_messaging/versions/17.0.0) يعتمد `firebase_core ^5`. لم أوسّع ترقية Firebase الرئيسية ضمن هذه الميزة حتى لا أغيّر مصادقة التطبيق أو Firestore أو App Check بلا اختبارات أوسع. رمز FCM لا يمكن قراءته من العميل عبر قواعد Firestore.

## قبل النشر

- راجع أن مشروع Firebase المقصود هو `agri-dahshory`؛ لا تنشر إلى مشروع آخر بالخطأ.
- الدالة المجدولة تتطلب خطة Firebase **Blaze** وتستخدم Cloud Scheduler وCloud Functions، وقد تترتب عليها تكلفة أو استهلاك حصص. راجع تفاصيل المشروع والخدمات في Firebase/Google Cloud Console، وضع تنبيهات ميزانية قبل التفعيل. لم تُفعّل خدمة أو عملية نشر من هذا المستودع.
- تأكد من تفعيل Firebase Cloud Messaging في المشروع. عند نشر الدالة، قد يطلب Firebase CLI تفعيل Cloud Functions وCloud Scheduler وCloud Build وArtifact Registry.
- تستخدم الخدمة Open-Meteo دون مفتاح API، وتجمع الأجهزة ذات الإحداثيات المقربة المتطابقة لتقليل الطلبات. راجع شروط مزود الطقس وحدوده عند التوسع أو الاستخدام التجاري.

## الاختبار والنشر

من جذر المستودع:

```bash
cd functions
npm ci
npm test
cd ..
```

بعد مراجعة المشروع والصلاحيات والقواعد، سجّل الدخول إلى Firebase CLI ثم انشر القواعد والدالة صراحةً إلى المشروع الصحيح:

```bash
firebase login
firebase deploy --project agri-dahshory --only firestore:rules,functions
```

النشر ينشئ Cloud Scheduler job للدالة `dispatchWeatherPushAlerts` تلقائياً، وفق [دليل Firebase للوظائف المجدولة](https://firebase.google.com/docs/functions/schedule-functions). لا تنفّذ نشر الإنتاج من CI؛ Workflow التحليل يكتفي ببناء واختبار الدالة. انشر القواعد والدالة من بيئة موثوقة بعد مراجعة المخرجات.

## اختبار التطبيق بعد النشر

1. انتظر نجاح نشر `dispatchWeatherPushAlerts` وافحص سجل Cloud Scheduler وCloud Functions.
2. ابنِ وثبّت أحدث APK من GitHub Actions، ثم سجّل الدخول وافتح بطاقة الطقس وحدد المحافظة أو الموقع.
3. فعّل «إشعارات الطقس على هذا الجهاز» ووافق على إذن الإشعارات. لا يرسل التطبيق إحداثيات الخادم قبل التفعيل؛ وتُقرب الإحداثيات قبل التخزين.
4. تحقق من إنشاء مستند واحد تحت `users/{uid}/weather_push_devices/{token}`. قواعد Firestore تمنع قراءة المستند من العميل وتسمح للحساب المالك فقط بإنشائه أو تحديثه أو حذفه.
5. انتظر دورة الجدولة التالية (حتى ثلاث ساعات) أو راجع السجلات. لا يصدر Push إلا إذا ظهر تنبيه ضمن الأيام الثلاثة المقبلة؛ حالة الاختبار داخل التطبيق منفصلة عن التنبيه الخادمي.
6. أوقف المفتاح أو سجّل الخروج وتأكد من حذف مستند الجهاز. اختبر كذلك وصول الرسالة والتعامل معها والتطبيق مفتوح، في الخلفية، وبعد إغلاقه، مع ملاحظة أن تسليم FCM قد يتأخر بحسب الشبكة وإعدادات النظام.

التنبيهات تقديرية وليست تحذيرات رسمية من هيئة الأرصاد. لم تُنشر Cloud Function أو القواعد من هذه التغييرات؛ بعد دمج الفرع، يلزم تنفيذ أوامر النشر أعلاه في المشروع الفعلي.
